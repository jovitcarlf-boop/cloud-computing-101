# Laboratory 5: Cloud Data Engineer

## Mission Overview

In this laboratory activity, I deployed and configured a professional-grade object storage server using MinIO and Docker. The mission simulated a real-world scenario where a client needed a scalable, secure storage solution for a photo-sharing application that would handle millions of user-uploaded images. This hands-on experience combined containerization skills from Mission 4 with cloud storage architecture concepts.

## Mission Objectives

By completing this laboratory, I demonstrated the ability to:

- Differentiate between Block, File, and Object Storage and understand their use cases
- Deploy an S3-compatible Object Storage server (MinIO) using Docker with environment variables
- Access cloud services through web interfaces using port forwarding in KillerCoda
- Create storage buckets and upload objects (files) to cloud storage
- Document cloud operations professionally using Markdown
- Maintain a well-organized GitHub Cloud Computing Portfolio with proper file structure

## Key Takeaways

This laboratory reinforced that cloud engineers must understand multiple storage paradigms and know when to apply each one. Object Storage's ability to scale infinitely and its cost-efficient pay-as-you-go model make it ideal for modern applications handling unstructured data. Docker's containerization capabilities made deploying a complex storage system as simple as running a single command, demonstrating the power of infrastructure-as-code principles.
